# Менеджер личных финансов — pet-проект на Python

## Цель
Разработать консольное приложение для учёта личных доходов и расходов. Закрепить функции, циклы, условия, списки, словари, обработку ошибок и JSON.

**Уровень:** начинающий. **Время:** 4–8 часов на базовую версию.

## Функциональные требования

Программа должна показывать меню:
```text
===== МОИ ФИНАНСЫ =====
1. Добавить доход
2. Добавить расход
3. Показать все операции
4. Показать баланс
5. Показать статистику
0. Выход
```

1. **Доход:** ввод положительной суммы и непустой категории; сохранение операции с типом `income`.
2. **Расход:** аналогично, с типом `expense`.
3. **Все операции:** вывод типа, суммы и категории; сообщение при пустом списке.
4. **Баланс:** сумма доходов минус сумма расходов.
5. **Статистика:** общая сумма доходов, расходов и баланс.
6. **Выход:** завершение приложения. До выхода меню повторяется.

## Модель данных
Используйте список словарей:
```python
transactions = [
    {"type": "income", "amount": 50000, "category": "Зарплата"},
    {"type": "expense", "amount": 1500, "category": "Продукты"}
]
```
`type` — `income` или `expense`, `amount` — положительное число, `category` — непустая строка. Для начала можно принимать только целые суммы; для копеек лучше использовать целые копейки или `decimal.Decimal`, а не `float`.

## Структура функций
| Функция | Назначение |
| --- | --- |
| `main()` | Меню и обработка выбора |
| `add_transaction()` | Добавление дохода или расхода |
| `show_transactions()` | Вывод всех операций |
| `get_balance()` | Расчёт и возврат баланса |
| `show_statistics()` | Вывод общей статистики |

Передавайте данные между функциями осмысленно. По возможности отделяйте вычисления от вывода.

## Обработка ошибок
Программа не должна завершаться с исключением при:
- вводе текста вместо суммы;
- нулевой или отрицательной сумме;
- пустой категории;
- несуществующем пункте меню;
- просмотре статистики без операций.

После ошибки покажите сообщение и разрешите повторить ввод или вернуться в меню.

- [ ] Сохранять операции в `transactions.json` при выходе.

- [ ] Обрабатывать повреждённый JSON понятным сообщением, не перезаписывая его без предупреждения.

Используйте стандартный модуль `json` и кодировку UTF-8.

### Этап 3 — дополнительные задачи (необязательно)
- [ ] Удаление ошибочной операции.
- [ ] Статистика расходов по категориям.
- [ ] Фильтрация по типу операции.
- [ ] Автоматические тесты.

## Проверочные сценарии
| Действие | Результат |
| --- | --- |
| Операций нет | Баланс, доходы и расходы = 0 |
| Доход 50000, расход 1500 | Баланс = 48500 |
| Расходы 100 и 250 | Общие расходы = 350 |
| Ввод `abc` вместо суммы | Ошибка ввода, приложение продолжает работу |
| Ввод `-5` или `0` | Операция не добавляется |
| Несуществующий пункт меню | Сообщение, возврат в меню |
| Перезапуск программы | Сохранённые операции загружаются |
